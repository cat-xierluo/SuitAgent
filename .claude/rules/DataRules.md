# 案件数据读写契约（DataRules）

**版本**: 1.0
**最后更新**: 2026-08-15
**说明**: 定义所有 Agent 对案件数据（case.yaml / 案件信息.md / 工时记录.md）的读写契约。本文件为规则层摘要；完整契约见 case-progress skill `references/contract.md`，字段字典见其 `references/schema.md`（v4.0 唯一权威）。

## 🚨 核心原则

**case.yaml 是案件状态唯一真值；一切写入必须经 case-progress 的 case_store CLI（或看板），禁止任何 Agent 手改 yaml**

手改是历史 5 套格式漂移的根因；`validate` 检测到漂移将拒绝后续写入。

## 📋 会话开始：加载

```bash
python3 .claude/skills/case-progress/scripts/case_store.py show <案件短码>
```

- 案情叙事按 `上下文.叙事文档` 指针读案件根目录的 `案件信息.md`（固定名）
- 深度任务按需读 `上下文.关键报告`（02/10 目录代表产出）
- **禁止**自行解析 yaml 代替 `show`——show 已按"锁定 > 手填 > 推断"解析程序阶段，并过滤已抵消期限

## 📋 会话结束：写回

| 变更 | 命令 |
| --- | --- |
| 新增任务 | `add-task <短码> <标题> [--priority] [--deadline]` |
| 推进任务 | `set-status <短码> <task_id> <todo\|in_progress\|done>` |
| 登记期限 | `add-deadline <短码> <名称> --end <日期> [--start <日期>] [--days N] [--basis 条文]` |
| 更新阶段 | `set-stage <短码> <阶段> [--lock]` |
| **工时记录** | `log-work <短码> <时长小时> <内容> [--date] [--task task_id] [--file 文书路径] [--lawyer]`——"何时做了什么工作"的结构化真值（计费依据）；自动重算总工时 |
| 校验 | `validate <短码>` |

- 叙事情节（事实/争议论述/策略）**不进 yaml**，写 `案件信息.md`，仅重大节点（立案/开庭/判决/调解）
- 过程产物（报告/文书/研究）输出到 02–11 目录，不回写 yaml
- 工时明细写 `工时记录.md`；聚合值由 CLI 维护

## 🔒 人工覆盖保护（引擎强制，Agent 亦须知）

1. `source: user` 的行：AI **永不覆写**——需变更时提示律师，或律师经看板操作（--actor user）
2. `生命周期状态 = 已结案`：仅律师手工标记，任何 Agent 不得设置或清除
3. `程序阶段锁定 = true`：不得改写程序阶段（可提示律师解锁）
4. AI 写入的行一律 `source: ai`（CLI 自动落，不可伪装 user）

## 🔄 工作流收尾（强制，skill 间协作）

复合工作流（被告应诉、证据质证、庭审后分析、法律服务方案、策略优化、原告起诉、制作委托材料）在 Reporter 之后，主 Agent **直接执行 case-progress skill 的"工作流收尾状态同步"流程**（加载状态 → 盘点产出 → 映射判断 → CLI 写回 → 校验汇报）——**不派发 subagent**（决策 #047：skill 协作为主）。工作流中的专业 Agent 不必各自写状态。

## 📁 文件分工速查

| 文件 | 职责 | 写入方式 |
| --- | --- | --- |
| `00 - 📅 日程管理/case.yaml` | 状态真值（任务/期限/阶段/时间线/证据索引/**工作记录**） | 仅经 case_store CLI（或看板） |
| `案件信息.md`（案件根，固定名） | 案情叙事（当事人细节/事实/争议论述/策略） | Agent 直接编辑，仅重大节点 |
| `00 - 📅 日程管理/工时记录.md`（固定名） | **手工便签/打印件**（结构化真值在 case.yaml 工作记录） | 律师手写或导出打印 |
| 02–11 目录 | 过程档案（分析/研究/证据/文书/报告） | 各工作流产出，不动 |
