# Command 元规范

**版本**: 1.1
**最后更新**: 2026-01-08
**说明**: 定义 `.claude/commands/` 目录下命令文件的统一结构、命名和格式规范

## 🎯 适用范围

本规范**仅适用于** `.claude/commands/` 目录下的命令配置文件。

**说明**：`.claude/skills/`、`.claude/rules/` 等其他目录下的文件有其特定的格式要求，不在本规范约束范围内。

## 📋 核心规范三要素

每个 Command 文件必须包含以下三个核心要素：

1. **文件命名规范**（kebab-case）
2. **YAML Frontmatter**（name + description）
3. **变更历史记录**（🔄 变更历史）

## 📝 文件命名规范

### 命名格式

命令文件统一使用 **kebab-case** 命名（小写字母 + 连字符）：

```text
command-name.md
```

### 命名模式

| 类型   | 命名规则                                  | 示例                              |
| :----- | :---------------------------------------- | :-------------------------------- |
| 命令类 | `动词-名词.md` 或 `动词-名词-宾语.md` | `new-case.md`                   |
| 工具类 | `工具名.md`                             | `2word.md`、`deepresearch.md` |
| 设置类 | `set-配置项.md`                     | `save.md`                         |

### 正确与错误示例

```text
# ✅ 正确
new-case.md
evidence-review.md
generate-trust-docs.md

# ❌ 错误
new_case.md           # 应使用连字符
NewCase.md            # 应使用小写
Evidence-Review.md    # 应使用小写
```

## 📋 YAML Frontmatter（必需）

每个 Command 文件必须以 YAML frontmatter 开头：

```yaml
---
name: command-name
description: 简洁描述命令的功能和用途
---
```

### 字段说明

| 字段            | 必需 | 说明                               | 示例                                 |
| :-------------- | :--- | :--------------------------------- | :----------------------------------- |
| `name`        | ✅   | 命令名称，与文件名一致（不含斜杠） | `new-case`                         |
| `description` | ✅   | 命令描述，说明功能和触发场景       | `为新案件创建标准化的工作目录结构` |

### 撰写要点

**name 字段**：

- 使用小写字母和连字符
- 与文件名保持一致（不含 `.md` 后缀）
- 简洁明确，体现命令功能

**description 字段**：

- 一两句话描述命令功能
- 说明解决的问题
- 明确适用场景
- 使用陈述语气（第三人称）

### 完整示例

```yaml
---
name: new-case
description: 为新案件创建标准化的工作目录结构，自动复制案件模板并初始化管理文件
---
```

```yaml
---
name: evidence-review
description: 对新证据进行全面的质证分析，评估证据的三性（真实性、合法性、关联性）
---
```

## 📅 变更历史规范

### 版本号规则

遵循**语义化版本（Semantic Versioning）**：

```text
主版本号.次版本号.修订号
例如：1.2.3
```

- **主版本号（Major）**：不兼容的API修改或重大功能变更
- **次版本号（Minor）**：向下兼容的功能性新增
- **修订号（Patch）**：向下兼容的问题修正

### 变更历史格式

每个 Command 文件必须以变更历史结尾：

```markdown
## 🔄 变更历史

| 版本   | 日期       | 更新内容                   |
| :----- | :--------- | :------------------------- |
| v1.2.0 | 2026-01-15 | 新增XXX功能，优化YYY参数   |
| v1.1.0 | 2026-01-10 | 新增XXX参数支持           |
| v1.0.1 | 2026-01-05 | 修复XXX问题               |
| v1.0.0 | 2026-01-01 | 初始版本                   |
```

### 变更记录撰写要点

1. **使用中文**：所有更新内容使用中文描述
2. **具体明确**：清晰说明变更的内容和影响
3. **关键词优先**：使用"新增"、"优化"、"修复"、"删除"、"重构"等关键词
4. **简洁扼要**：每条记录控制在20字以内
5. **倒序排列**：最新版本在最上面

- [ ] name 字段与文件名一致

### 内容检查

- [ ] description 清晰描述命令功能
- [ ] 变更历史存在且格式正确
