## 📁 核心文件结构

SuitAgent案件模板采用三层文件结构，支持AI快速加载和人工详细查阅的分离设计。

### 1. 根目录文件（AI优先）

**`[案件编号]案件信息.md`**

- **位置**: `[案件编号]/[案件编号]案件信息.md`
- **用途**: 案件管理看板，所有Agent的首要上下文来源
- **内容**: 案件基本信息、当事人信息、争议焦点、任务清单、期限管理等
- **特点**: 轻量级，AI可快速加载和解析

### 2. 日程管理目录文件（人工查阅 + 机器真值）

**`00 - 📅 日程管理/工时记录.md`**（v4.0 起固定名，无编号前缀）

- **位置**: `[案件编号]/00 - 📅 日程管理/工时记录.md`
- **用途**: 详细工时记录与费用核算
- **内容**: 月度工时统计、文件清单、案件进展摘要、费用汇总等
- **特点**: 详细完整，支持审计查阅，AI不优先加载

**`00 - 📅 日程管理/case.yaml`**（v4.0 canonical，固定文件名）

- **位置**: `[案件编号]/00 - 📅 日程管理/case.yaml`
- **用途**: **案件状态唯一真值**（case-progress skill 契约，字段字典见其 `references/schema.md`）
- **内容**: meta（标识四分）/ 案件基本信息（状态二分）/ 当事人与代理 / 法定期限（列表化）/ 任务（**唯一任务真源**）/ 案件时间线 / 开庭与听证 / 证据索引 / 费用信息 / 上下文指针 / 同步 / 更新历史
- **特点**: **唯一写入方式 = case_store CLI（或看板），任何 Agent 禁止手改**；Scheduler 负责期限计算并经 CLI 落盘；新建案件由 new-case v4.0 模板生成，存量案件经 M4 迁移

## 🔄 文件职责分工

| 文件                  | 主要使用者          | 更新频率   | 职责                       |
| --------------------- | ------------------- | ---------- | -------------------------- |
| **案件信息.md** | 所有Agent、承办律师 | 重大节点（立案/开庭/判决/调解） | 案情叙事、上下文来源   |
| **工时记录.md** | 承办律师、财务      | 每天/每周  | 详细工时记录、费用核算     |
| **case.yaml**   | case_store（case-progress CLI） | 每次会话结束/看板操作 | 案件状态唯一真值（任务/期限/阶段）；Scheduler 计算期限数据经 CLI 写入 |

## 📊 Agent分层架构与目录映射

SuitAgent采用四层架构设计，将10个Agent按职能分为4个层级：

### 📥 输入层 (Input Layer) - 文档数据采集

#### DocAnalyzer

- **主要输出**: `02 - 📄 案件分析`
- **次要输出**: `04 - 📤 客户提供`、`07 - 📥 对方提交`、`08 - 🏛️ 法院送达`、`09 - 🎯 庭审笔录`
- **功能**: 分析各类法律文档，提取结构化信息

#### EvidenceAnalyzer

- **主要输出**: `05 - 📎 证据材料`
- **次要输出**: `07 - 📥 对方提交`
- **功能**: 深度分析证据材料，评估证明力

### 🔍 分析层 (Analysis Layer) - 智能分析与研究

#### IssueIdentifier

- **主要输出**: `03 - 🔍 法律研究`
- **功能**: 识别和归类争议焦点

#### Researcher

- **主要输出**: `03 - 🔍 法律研究`
- **次要输出**: `11 - 📚 参考文件`
- **功能**: 法条解读、判例检索、法律适用研究

#### Strategist

- **主要输出**: `02 - 📄 案件分析`
- **功能**: SWOT分析、策略制定、风险评估

### 📝 输出层 (Output Layer) - 文书生成与报告

#### Writer

- **主要输出**: `06 - 📝 法律文书`
- **次要输出**: `01 - 🤝 委托材料`
- **功能**: 起草各类法律文书

#### Reporter

- **主要输出**: `10 - 📊 综合报告`
- **功能**: 整合所有内容，生成综合报告

#### Summarizer

- **主要输出**: `10 - 📊 综合报告`
- **次要输出**: `09 - 🎯 庭审笔录`
- **功能**: 生成各类摘要和简报

### ⚙️ 支持层 (Support Layer) - 质量保证与辅助

#### Scheduler

- **主要输出**: `00 - 📅 日程管理`
- **次要输出**: `08 - 🏛️ 法院送达`
- **功能**: 期限管理、工时统计

#### Reviewer

- **主要输出**: 无（不直接输出文件）
- **功能**: 智能审查器，质量把关专家

## 📋 完整目录结构（12层架构）

案件目录采用12层标准化结构，Agent输出遵循以下映射关系：

```
00 - 📅 日程管理        → Scheduler（期限管理、工时统计）
01 - 🤝 委托材料        → Writer（委托合同、授权书）
02 - 📄 案件分析        → DocAnalyzer, Strategist（案件分析、策略）
03 - 🔍 法律研究        → IssueIdentifier, Researcher（争议焦点、法条检索）
04 - 📤 客户提供        → DocAnalyzer（客户材料）
05 - 📎 证据材料        → EvidenceAnalyzer（证据分析、质证）
06 - 📝 法律文书        → Writer（起诉状、答辩状等）
07 - 📥 对方提交        → DocAnalyzer, EvidenceAnalyzer
08 - 🏛️ 法院送达        → DocAnalyzer, Scheduler（传票、判决书）
09 - 🎯 庭审笔录        → DocAnalyzer, Summarizer（庭审记录）
10 - 📊 综合报告        → Summarizer, Reporter（案件摘要、报告）
11 - 📚 参考文件        → Researcher（参考案例、法条）
```

## 💡 使用说明

### AI处理阶段

- **优先读取**: `case_store show <案件短码>` 加载结构化状态 + 根目录 `案件信息.md` 获取案情叙事（契约见 [`DataRules.md`](./DataRules.md)）
- **Agent输出**: 按照目录映射规范输出到对应目录
- **状态同步**: 工作流收尾由主 Agent 执行 case-progress skill 的状态同步流程，将任务/期限/阶段变更写回 case.yaml；叙事情节重大节点更新案件信息.md

### 人工记录阶段

- **工时记录**: 在 `工时记录.md`中记录详细工作内容和时长
- **期限管理**: Scheduler 计算期限并经 case_store CLI 写入 case.yaml；"已结案"仅律师手工标记
- **目录定位**: 通过标准化目录结构快速定位各类文档
