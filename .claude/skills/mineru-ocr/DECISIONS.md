## D-2026-03-31-01 引入 Auto 双通道解析
- 日期: 2026-03-31
- 背景: 官方已提供免登录轻量接口，现有技能却仍强制用户先配置 Token，首次使用门槛过高。
- 决策: 默认采用 Auto 模式；未配置 Token 时使用官方免登录轻量接口，已配置 Token 时只走现有标准 API。
- 影响: 新用户可开箱即用；老用户既有 Token 配置与标准 API 归档链路保持不变。
- 状态: 已执行

## D-2026-03-31-02 保留归档能力，不改造成纯官方 CLI 包装
- 日期: 2026-03-31
- 背景: 官方 skill 更偏向 API/CLI 包装，而现有技能的核心价值之一是 archive 回溯能力，包括 Markdown、接口结果和图片相关资源的保留。
- 决策: 不直接重写为官方 CLI 包装，继续保留现有脚本式调用与 archive 目录设计，只在入口层增加轻量接口分支。
- 影响: 技能仍保留本地可追溯性；轻量接口结果也会写入 archive，减少功能退化。
- 状态: 已执行

## D-2026-03-31-03 清理冗余配置
- 日期: 2026-03-31
- 背景: `MINERU_USER_TOKEN` 和多项调试/锁配置未被实际使用，且官方 skill 也未暴露这些概念，容易造成配置误导。
- 决策: 从模板中移除 `MINERU_USER_TOKEN` 及未使用配置，仅保留当前脚本真正会读取的最小配置集。
- 影响: 配置模板更清晰，减少复制模板后带着伪配置运行的风险。
- 状态: 已执行

## D-2026-03-31-04 扩展远程输入源
- 日期: 2026-03-31
- 背景: 官方技能支持本地文件、远程文档 URL 和网页提取，而现有技能仅支持本地文件，覆盖面不足。
- 决策: 在保持当前 archive 设计的前提下，为现有脚本增加远程文档 URL 支持；网页 URL 仅在 Token 模式下启用。
- 影响: skill 使用场景扩展到“本地文件 + 远程文档 + 网页 URL”；同时保持轻量模式与标准模式的能力边界清晰。
- 状态: 已执行

## D-2026-03-31-05 Token 自检采用诊断探测
- 日期: 2026-03-31
- 背景: 官方 CLI 提供 `auth --verify`，现有 skill 缺少类似诊断入口。
- 决策: 为脚本增加 `checktoken` 诊断入口，通过携带 Authorization 访问标准 API 任务查询接口进行轻量诊断，不触发实际解析任务。
- 影响: 用户可更快判断 Token 是否有效；自检结果依赖 API 地址与网络可达性。
- 状态: 已执行

## D-2026-03-31-06 云端优先，不适配自部署 FastAPI 协议
- 日期: 2026-03-31
- 背景: 官方自部署 `mineru-api` / `mineru-router` 使用 `/tasks`、`/file_parse` 等接口，与云端 `api/v4` 协议不同；若同时兼容会显著增加维护复杂度。
- 决策: 当前 skill 只维护官方云端模式；自部署场景交由官方 CLI / SDK 处理，不在本 skill 内再接入第二套协议。
- 影响: skill 的使用路径更清晰；如后续确有需求，再单独设计 `self-hosted` 模式。
- 状态: 已执行

## D-2026-04-01-01 法律文档场景只补最有价值的精准参数
- 日期: 2026-04-01
- 背景: 官方精准 API 提供 `model_version`、`page_ranges`、`extra_formats`、`callback` 等多项高级参数，但当前 skill 面向法律文档 OCR 与归档回溯，不适合一次性做成全量参数面板。
- 决策: 仅补充 `MINERU_MODEL_VERSION` 与 `MINERU_PAGE_RANGES`。默认模型保持 `pipeline`，只在复杂版面场景下允许切换到 `vlm`；其余高级参数暂不接入。
- 影响: skill 保持简洁，同时为法律场景提供两个最实用的精准控制开关。
- 状态: 已执行

## D-2026-04-01-02 Token 读取兼容官方 CLI，但本 skill 配置优先
- 日期: 2026-04-01
- 背景: 官方 skill / CLI 会把 Token 存到 `~/.mineru/config.yaml`；若当前 skill 不兼容读取，用户在两套入口之间切换时需要重复配置。
- 决策: 增加对 `~/.mineru/config.yaml` 的回退读取，但保持本 skill 的 `.env` 和环境变量优先，避免覆盖现有本地配置。
- 影响: 已使用官方 `mineru-open-api auth` 的用户可以无缝复用 Token；你自己的 `.env` Token 不受影响。
- 状态: 已执行

- 影响: 提升技能的可维护性和可追溯性，便于未来功能迭代。

## D-2025-01-07-02 使用 config/ 目录存储配置
- 日期: 2026-01-07（追溯决策）
- 背景: 技能需要存储 API Token 等敏感配置信息，不应硬编码在脚本中。
- 决策: 使用 `config/` 目录存储配置文件，包含 `.env.example` 模板和 `.env` 实际配置，避免将敏感信息提交到版本控制。
- 影响: 提升安全性，用户可自行配置而不需修改代码；`.env` 应加入 `.gitignore`。
- 状态: 已执行

## D-2025-01-07-03 保留 archive/ 归档目录
- 日期: 2026-01-07（追溯决策）
- 背景: 转换任务会产生中间文件（JSON、图片、原始文件），这些文件对调试和历史追溯有价值。
- 决策: 在技能目录内保留 `archive/` 目录，按 `日期_时间_文件名/` 格式归档每次转换的完整数据。
- 影响: 便于问题排查和结果追溯；归档目录可能占用较大空间，需要定期清理。
- 状态: 已执行

## D-2025-01-07-04 选择 MinerU API
- 日期: 2026-01-07（追溯决策）
- 背景: 需要将 PDF、Word、PPT 等文档高质量转换为 Markdown，要求保留表格、公式等复杂格式。
- 决策: 选择 MinerU API 服务，因其支持 OCR、表格识别、公式识别，且转换质量高。
- 影响: 依赖外部 API 服务；按当前规则，Token 有效期为 90 天，需要定期更新；无网络时无法使用。
- 状态: 已执行

## D-2025-01-07-05 使用 JXA 脚本
- 日期: 2026-01-07（追溯决策）
- 背景: 需要调用 MinerU API 并处理轮询逻辑，要求跨平台兼容。
- 决策: 使用 JavaScript for Automation (JXA) 编写 `scripts/convert.js`，通过 `osascript` 在 macOS 上调用，便于 JSON 处理和 HTTP 请求。
- 影响: 依赖 macOS `osascript` 运行环境；跨平台兼容性需要考虑（当前主要针对 macOS）。
- 状态: 已执行
