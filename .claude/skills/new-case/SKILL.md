# New Case - 创建新案件

将案件原始材料整理成SuitAgent标准12层目录结构，生成案件信息看板（案件信息.md）、工时记录（工时记录.md）和期限管理文件（.yaml）。

## 适用场景

1. 新建案件档案，需要建立标准化目录结构
2. 已有案件材料，需要整理成统一格式
3. 接收新案件，需要快速搭建案件框架
4. 整理历史案件材料，迁移到标准化结构

## 触发方式

### 自然语言触发
- "整理这个案件材料：/path/to/case-folder"
- "帮我建立案件结构：案件在 /path/to/case"
- "创建新案件"
- "新建案件"

### 参数化触发
支持以下参数（通过自然语言或结构化方式传递）：

| 参数 | 必需 | 说明 | 示例 |
|------|------|------|------|
| `--case-id` | 是 | 案件编号 | `[2025]京0105民初1234号` 或 `张三诉李四合同纠纷` |
| `--client-name` | 否 | 委托人姓名/公司名 | `北京科技有限公司` |
| `--case-type` | 否 | 案件类型 | `民事`/`刑事`/`行政` |
| `--case-cause` | 否 | 案由 | `合同纠纷` |
| `--opposite-party` | 否 | 对方当事人 | `上海某某公司` |
| `--input-dir` | 否 | 案件材料目录 | `/path/to/materials` |

**使用示例**：
```
"创建新案件，案件编号 [2025]京0105民初1234号，委托人北京科技有限公司，案由合同纠纷，对方当事人上海某某公司"
```

## 工作流程

### 第一步：分析输入材料

1. **扫描案件文件夹**，列出所有文件
2. **识别材料类型**：
   - 法律服务方案（.md/.docx）
   - 聊天记录/沟通记录
   - 证据材料（图片、PDF）
   - 委托材料
   - 身份证明文件
   - 其他文档
3. **提取关键信息**：
   - 当事人信息（原告、被告）
   - 案件类型/案由
   - 涉案金额（如有）
   - 对方当事人信息

### 第二步：建立标准目录结构

基于 skill 内置模板创建12层目录。

> 详细目录结构规范见 [references/case-structure.md](references/case-structure.md)
> 各目录的子目录结构、关联Agent、输出文件示例见 [references/directory-guide.md](references/directory-guide.md)

### 第三步：材料分类整理

> 详细材料分类映射见 [references/case-structure.md](references/case-structure.md)

### 第四步：生成案件信息看板

根据模板 [references/case-info-template.md](references/case-info-template.md) 生成案件信息.md，包含：

1. **案件基本信息**
   - 案件名称：格式「原告+等+诉+被告+等+案由」
   - 案件编号：格式「YYMMNN+当事人+案由」
   - 案由、案件类型、当前阶段

2. **当事人信息**
   - 原告：姓名、类型、证件号码、地址
   - 被告：姓名、类型、证件号码、法定代表人

3. **争议焦点**（从法律服务方案提取）
   - 主要争议点
   - 次要争议点

4. **时间线**
   - 律所立案日期
   - 预计时间节点

5. **费用跟踪**
   - 律师费、诉讼费预估

6. **任务清单**
   - 按4阶段法律服务方案分解任务

7. **近期重要任务清单**（含今日待办、明日待办）

8. **法定期限管理**（应诉15天、举证30天、上诉15天等标准期限表格 + 期限风险预警）

9. **风险提示与注意事项**（当前风险 + 策略建议）

10. **更新历史**（标准表格格式）

### 第五步：生成工时记录和期限管理

1. **工时记录**：`00 - 📅 日程管理/[案件编号]工时记录.md`
   > 详细结构见 [references/timesheet-template.md](references/timesheet-template.md)
   > 包含：本月工时统计表、12目录文件清单、案件进展摘要、累计工时统计、重要说明与备注

2. **期限管理**：`00 - 📅 日程管理/[案件编号].yaml`
   > 详细段落结构见 [references/yaml-schema.md](references/yaml-schema.md)
   > 标注 `🔧 初始化` 的段落在 case-setup 时填充；标注 `⏳ 后续` 的段落留空供后续 Agent 填充

### 可选第六步：生成法律服务方案

如材料中包含初步沟通记录或客户需求描述，可基于 [references/service-proposal-template.md](references/service-proposal-template.md) 生成法律服务方案到 `01 - 🤝 委托材料/` 目录。

## 关键规则

### 案件编号规则

格式：`{年}{月}{序号} {原告简称} 与 {被告简称} {案由}`

示例：
- `260221 张家宁 与 pokebone 模型 著作权`
- `260315 甲公司 与 乙公司 合同纠纷`

### 案件名称规则

格式：`{原告}+等+诉+被告}+等+案由+案`

示例：
- `张家宁 诉 pokebone 模型 著作权侵权案`
- `甲公司 诉 乙公司 合同纠纷案`

### 文件命名规则

- 案件信息文件：`[案件编号] 案件信息.md`
- 工时记录：`[案件编号] 工时记录.md`
- 期限管理：`[案件编号].yaml`
- 其他文件使用中文描述，日期前缀格式：`YYMMDD `

## 时间要求

使用系统当前时间（通过 `date "+%Y-%m-%d"` 获取），确保：
- 文档创建时间为当前日期
- 时间线逻辑正确（过去→现在→未来）
- 剩余天数计算准确

## 输出验证

完成案件整理后，确认：

- [ ] 12层目录结构已创建
- [ ] 所有材料已分类移动到对应目录
- [ ] 案件信息.md已生成，包含完整基本信息
- [ ] 工时记录.md已创建
- [ ] .yaml期限管理文件已创建
- [ ] 文件命名符合规范
- [ ] 时间逻辑正确

## 禁止事项

- 禁止在案件档案中记录项目自身的SuitAgent系统信息
- 禁止创建额外的说明文档或README
- 禁止遗漏任何已有材料
- 禁止虚构案件信息
